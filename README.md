# U89 Studio OS

موقع عبد الوهاب بن سليمان السويد ونظام تشغيل الاستوديو في تطبيق عربي واحد. الواجهة العامة للتعريف والخدمات والأعمال، وبعد الدخول تظهر مساحة مستقلة للمالك والعميل والمتعاون.

## ما أصبح جاهزاً

- موقع تسويقي منفصل عن تفاصيل المشاريع الداخلية.
- نموذج طلب خدمة يحفظ بيانات التواصل، وسيلة التواصل المفضلة، قناة الإشعارات، الخدمة، الهدف، الجمهور، الميزانية والموعد.
- وضع محلي متكامل لاختبار السيناريو من 13 إجراء قبل ربط أي خدمة خارجية.
- وضع متصل يستخدم Supabase Auth وPostgres وStorage تلقائياً عند إضافة مفاتيح البيئة.
- صلاحيات داخل قاعدة البيانات للمالك والمدير والمحاسب والعميل والمتعاون.
- مسار تشغيلي محكوم: الطلب، البريف، عرض السعر، العقد، الدفعات، التنفيذ، البروفات، التسليم والمتابعة.
- قوالب بريف لكل خدمة، مع إمكانية تعديل الأقسام والأسئلة من لوحة التحكم.
- عروض سعر قابلة للتحرير، وخطط دفعات يجب أن يكون مجموعها 100%.
- عقد مستقل عن العرض، ببنود أولية قابلة للتعديل ثم يقفل نصه بعد أول توقيع، مع تسجيل هوية المستخدم ووقت قبول كل طرف.
- فواتير عميل غير ضريبية، ومطالبات تقديم خدمة للمتعاونين.
- نسخ طباعة عربية يمكن حفظها PDF للعروض والعقود وفواتير العميل وفواتير تقديم الخدمة.
- سعر مستقل لكل قطعة ولكل متعاون بعملات SAR وUSD وEUR.
- دفتر حركة مالية لا يحول العملات الأجنبية إلى الريال إلا بسعر صرف مسجل وقت السداد.
- عقود تسويقية محددة البداية والنهاية، مع طابور طلبات مستقل وإسناد لكل طلب.
- نموذج تفعيل للعقد التسويقي من ملف العميل، يفتح فوراً مكان الطلب الدوري في بوابة العميل.
- ملفات خاصة للمشروع مع روابط مؤقتة، ولا يرى العميل إلا الملفات المنشورة له.
- مراجعة داخلية إلزامية لملف البروفة قبل أن تفتحه الإدارة للعميل.
- رفع إيصال مرتبط بالفاتورة نفسها، ورفعه للمراجعة من شاشة الحسابات قبل تسجيل التحصيل.
- رفع حزمة التسليم من المشروع، ثم منع فتحها للعميل حتى اكتمال الفواتير.
- متابعة رضا العميل بعد تأكيد الاستلام، ثم إغلاق المشروع بالتقييم والملاحظة.
- دعوات بريدية للحسابات من الخادم، دون كشف مفتاح الإدارة في المتصفح.
- طابور إشعارات للبريد وواتساب، مع سجل للمحاولات والأخطاء.
- مركز إشعارات داخل المنصة يعرض إشعارات المستخدم نفسه ويسجل قراءتها دون تعطيل محاولات الإرسال الخارجي.
- مركز «الربط والإطلاق» يوضح ما تم ربطه وما يزال ينتظر الإعداد.
- حفظ محلي للفواتير والمستندات والبريفات التجريبية حتى بعد تحديث الصفحة.
- وضع فاتح وداكن وتصميم متجاوب للجوال.

## التشغيل المحلي السريع

```bash
npm install
npm run dev
```

افتح `http://localhost:5173`. إذا لم توجد متغيرات Supabase، يعمل الموقع تلقائياً في وضع التجربة المحلية.

للتأكد من البناء ومخطط SQL والنصوص:

```bash
npm run check
```

## تفعيل قاعدة البيانات

1. أنشئ مشروع Supabase.
2. افتح SQL Editor وشغل الملف:
   `supabase/migrations/202608050001_u89_studio_os.sql`
3. من Authentication > Users أنشئ مستخدم المالك بالبريد الذي ستدخل به.
4. انسخ UUID الخاص بالمستخدم.
5. افتح `supabase/OWNER_SETUP.sql` واستبدل UUID والبريد والجوال ثم شغله.
6. انسخ `.env.example` إلى `.env.local` وأضف Project URL وPublishable key.
7. أعد تشغيل `npm run dev` وسجل الدخول من «دخول المنصة».
8. افتح إعدادات العمل واحفظها مرة واحدة لمزامنة قوالب البريف الثمانية.

استخدم `VITE_SUPABASE_PUBLISHABLE_KEY` في المتصفح. مفتاح `SUPABASE_SERVICE_ROLE_KEY` مخصص لوظائف Vercel فقط ولا يوضع أبداً في متغير يبدأ بـ `VITE_`.

## المستخدمون والصلاحيات

- المالك: كل التشغيل، المالية، الموقع، الفريق والصلاحيات.
- المدير: التشغيل والمشاريع والفريق دون نقل ملكية المساحة.
- المحاسب: الفواتير والمطالبات ودفتر الحركة.
- العميل: مشاريعه وبريفاته وعروضه وعقوده وفواتيره وملفاته المنشورة فقط.
- المتعاون: المهام المسندة، المصادر المتاحة، البروفات، أسعاره ومطالباته فقط.

لا يختار المستخدم دوره عند الدخول. الدور محفوظ في جدول `memberships` وتطبقه سياسات Row Level Security داخل Postgres.

## الإشعارات

المسار الإنتاجي الموصى به:

1. ينشئ حدث المشروع سجلاً في جدول `notifications`.
2. يستدعي Supabase Database Webhook المسار `/api/notifications/dispatch` مع ترويسة `x-u89-webhook-secret`.
3. ترسل وظيفة Vercel البريد عبر Resend وواتساب عبر قالب Meta معتمد.
4. يشغل Vercel Cron معالجة احتياطية مرة يومياً للسجلات التي لم ترسل.
5. تتوقف إعادة المحاولة بعد خمس محاولات، ويظهر الخطأ في السجل.

الإرسال كل عشر دقائق عبر Vercel Cron يحتاج خطة تسمح بتكرار أعلى. الإعداد الافتراضي اليومي متوافق مع Hobby ويعمل كشبكة أمان، بينما Database Webhook يوفر الإرسال الفوري.

## النشر

المشروع جاهز لـ Vercel عبر `vercel.json`:

```bash
npm run build
```

مجلد الإخراج هو `dist`. أضف متغيرات `.env.example` في Vercel Settings > Environment Variables ثم أعد النشر. التفاصيل الكاملة في `DEPLOYMENT.md`.

## حدود يجب معرفتها

- قبول العقد داخل النظام يسجل المستخدم والوقت، لكنه لا يساوي خدمة توقيع إلكتروني مؤهلة قانونياً في كل حالة. راجع الصياغة وآلية التوقيع مع مختص قانوني قبل الاستخدام النهائي.
- الدفع الحالي مبني على التحويل البنكي ورفع الإيصال ثم اعتماد التحصيل من الإدارة. لا توجد بوابة دفع بالبطاقات ما لم تضاف لاحقاً.
- إرسال واتساب يحتاج حساب Meta Business وقالب رسالة معتمداً.
- لا تستخدم بيانات عملاء حقيقية قبل تطبيق ملف الترحيل، إنشاء المالك، اختبار سياسات الصلاحيات، واستكمال النسخ الاحتياطي.
